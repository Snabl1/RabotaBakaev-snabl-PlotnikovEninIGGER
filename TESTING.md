# Тестирование: как проверяем требования

В проекте тестирование уже сделано как единый сценарий “по пунктам” (Selenium + качество кода + БД + нагрузка + сеть + отчёты).

## 1) Что проверяется автоматически

- **Функциональные требования (UI / E2E)**: Selenium сценарии (логин, навигация, CRUD базовых сущностей, контроль доступа).
- **Качество кода**:
  - `php -l` по всем `.php` файлам (если `php` доступен в PATH)
  - `phpcs --standard=PSR2` при наличии `phpcs` (опционально)
  - метрика “сложности” по счётчикам (операторы/операнды/циклы/условия и т.п.) — для отчёта.
- **Данные**: проверка БД на критические пустоты (если заданы `MYSQL_*`).
- **Нефункциональные**:
  - нагрузка (RPS/время ответа + график)
  - сеть (задержки/потери/скорость + график)
- **Отчётность (артефакты прогона)**:
  - `selen/reports/latest_result.json` + архив `result_*.json`
  - `selen/reports/junit_latest.xml` + архив `junit_*.xml`
  - `selen/screenshots/.../screenshots_summary.html` + скриншоты (если Selenium запускался)

## 2) Что проверяется вручную

См. `selen/MANUAL_CHECKLIST.md`. Ручной слой нужен для:

- UX/тексты/визуал (авто‑проверкой трудно)
- пограничные кейсы и “плохие” вводы
- кросс‑браузер/адаптивность
- плавающие дефекты (фиксируем частоту и условия)

## 3) Фишки, которые встроены (из практик зрелых команд)

- **Наборы (smoke/regression/full)**: быстрый прогон для “жив ли стенд” и полный перед сдачей.
  - В веб‑интерфейсе `report.php` появился выбор набора.
  - Переменная окружения: `TEST_SUITE=smoke|regression|full`.
- **JUnit XML отчёт**: стандартный формат для CI (парсится большинством систем).
  - Файл: `selen/reports/junit_latest.xml` (+ архив по времени).
- **Ретраи Selenium**: уменьшают “флейку” из‑за таймингов.
  - Переменная: `SELENIUM_RETRIES=0..3`.

## 4) Как запускать

### Через веб (рекомендуется)

- Откройте `report.php`
- Выберите “Набор” и “Ретраи Selenium”
- Нажмите “Запустить тесты”

### Из консоли (PowerShell)

```powershell
cd .\selen
pip install -r .\requirements.txt

$env:TEST_SUITE="smoke"
$env:SELENIUM_RETRIES="2"
python .\main.py "http://localhost:3000"
```

## 5) Как расширять (коротко)

- **Новый автосценарий UI**: добавить метод в `PHPSiteTester` и включить его в список `selected` в `run_all_tests()`.
- **Новый smoke‑кейс**: добавить в “быстрый” фильтр для `suite == "smoke"`.
- **Новый критерий/метрика**: положить результат в `latest_result.json` (как сделано для `code_complexity`, `network_stats`).
