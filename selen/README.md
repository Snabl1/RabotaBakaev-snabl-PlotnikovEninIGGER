# Сценарий тестирования «Танковая База»

Скрипт по пунктам из `t.txt`:

1. **Логин и пароль** — вход под админом (Selenium), затем все остальные тесты под этой сессией.
2. **Проверка соответствия кода стандартам** — запуск `php -l` по всем `.php` файлам проекта.
3. **Проверка БД на пустоты** — подключение к MySQL и проверка ключевых таблиц на NULL/пустые обязательные поля (нужны переменные окружения).
4. **Бекапирование** — копирование PHP/CSS в папку `backup/YYYYMMDD_HHMMSS` (включается переменной окружения).
5. **Нагрузочная статистика** — серия запросов к сайту, вывод RPS и времени ответа (мин/макс/средн).
6. **Критерии t2.txt** — результаты Selenium помечаются как: *Валидность*, *Верификация*, *Свой (безопасность)*.
7. **Сложность кода t2.txt** — счётчики символов/операторов/операндов/циклов/условий/пробелов/энтеров (пишется в веб‑отчёт).

## Установка

```bash
cd selen
pip install -r requirements.txt
```

Нужны: **Chrome** и **ChromeDriver** (или Selenium 4 с автоматическим менеджером драйвера). В PATH должен быть **PHP** для проверки синтаксиса.

## Запуск

```bash
# По умолчанию URL берётся из config_test.py (или BASE_URL)
python main.py

# Свой URL
python main.py http://localhost:3000
```

## Наборы тестов (smoke/regression/full)

Как в “взрослых” пайплайнах: быстрый прогон для проверки, что “живое”, и полный прогон перед сдачей.

- `TEST_SUITE=smoke`: запускает быстрый UI‑набор и пропускает нагрузку/сеть и проверку БД
- `TEST_SUITE=regression`: обычный прогон (UI + БД + нагрузка/сеть)
- `TEST_SUITE=full`: всё (по сути как `regression`, но можно расширять)

Пример (Windows cmd):

```cmd
set TEST_SUITE=smoke
set SELENIUM_RETRIES=2
python main.py http://localhost:3000
```

## Ретраи Selenium (устранение “флейки”)

E2E‑тесты иногда падают из‑за таймингов/рендера. Можно включить ретраи:

- `SELENIUM_RETRIES=0..3` (по умолчанию 1)

## Конфигурация

Файл **`config_test.py`** (или переменные окружения):

| Переменная     | Описание                    | По умолчанию           |
|----------------|-----------------------------|------------------------|
| `BASE_URL`     | Адрес сайта                 | `http://localhost:3000`     |
| `LOGIN_USER`   | Логин админа                | `admin`                |
| `LOGIN_PASS`   | Пароль админа               | `admin123`             |
| `PROJECT_ROOT` | Корень проекта (для php -l и бекапа) | родитель папки `selen` |
| `DO_BACKUP`    | Делать бекап до тестов      | выключен               |
| `MYSQL_HOST`   | Хост БД (для проверки пустот) | пусто — проверка пропущена |
| `MYSQL_DB`     | Имя БД                      | `project_Bakaev`       |
| `MYSQL_USER`   | Пользователь БД             | —                      |
| `MYSQL_PASS`   | Пароль БД                  | —                      |

Пример с бекапом и проверкой БД (Windows):

```cmd
set DO_BACKUP=1
set MYSQL_HOST=134.90.167.42
set MYSQL_PORT=10306
set MYSQL_USER=Bakaev
set MYSQL_PASS=твой_пароль
python main.py http://твой-сайт
```

Дополнительные переменные (t2.txt):

| Переменная | Описание | По умолчанию |
|---|---|---|
| `TEST_CRITERIA` | Какие критерии Selenium запускать: `validity,verification,custom` | все |
| `AUTO_GIT` | Делать автосейв в git (внутри тест‑прогона) | `1` |
| `GIT_SAVE_SCHEME` | Схема: `per_run` или `before_after_fix` | `per_run` |
| `AUTO_FIX_PSR` | Пытаться авто‑фиксить PSR-2 через `phpcbf` (создаёт смысл “до/после”) | `0` |

## Результаты

- В консоли — таблица тестов и статистика.
- Скриншоты — в `selen/screenshots/YYYYMMDD_HHMMSS/`.
- HTML-отчёт со скриншотами — `screenshots/.../screenshots_summary.html`.
- JUnit XML (для CI) — `selen/reports/junit_latest.xml` (и архив по времени `junit_YYYYMMDD_HHMMSS.xml`).
